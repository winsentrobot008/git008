# AI-WORKFLOW 项目治理文件

> **业务项目级治理规则**
> 本文件收纳了原宪法附录《工程治理体系（Cline‑Anti‑Freeze 扩展）》中涉及 AI-WORKFLOW 具体实现的规则。
> 宪法（`CONSTITUTION.md`）仅回答通用纪律问题；业务实现约束下沉至此。

---

## 1. 总则

- 不得修改任何已稳定运行的功能，除非明确允许。
- 不得修改 app.py 的核心逻辑（DeepSeek 调用、UI 主结构）。
- 不得修改 .env 或环境变量加载方式。
- 不得在 main 分支开发，所有开发必须在 feature 分支进行。
- 所有修改必须通过回归测试验证后才能合并。
- 所有新增文件必须经过 CEO 或设计总监确认。
- 不确定的操作必须先询问，不得擅自执行。

---

## 2. 分支管理

- 所有开发必须在 feature 分支进行。
- 禁止在 main 分支直接开发。
- 所有修改必须通过 PR，由 CEO 或设计总监审核。

---

## 3. 文件保护

受保护文件（禁止修改）：
- `app.py`（核心结构）
- `.env`
- `requirements.txt`（除非明确要求）
- `assets/lottie/` 下的现有文件
- `.gitignore`
- `README.md`（除非明确要求）

允许修改：
- 新增模块、utils、emotion_xxx.py、animation_xxx.py、CSS/JS

---

## 4. 回归测试

每次修改后必须执行：
1. `python app.py`
2. 输入测试文本
3. 检查 DeepSeek 回复、动画、UI 是否正常

如有失败，必须自动执行：
```bash
git reset --hard HEAD
```

---

## 5. 环境变量规范

- 不得修改 `.env`
- 不得修改 `load_dotenv()`
- 不得创建新的环境变量加载方式
- 不得硬编码 API Key

---

## 6. 任务执行规范

执行任务前必须：
- 复述任务目标
- 列出将修改的文件
- 列出不会修改的文件
- 列出风险点
- 列出回归测试计划

经 CEO 或设计总监确认后才能执行。

---

## 7. 自动回滚机制

如遇错误、异常、API 失败、UI 崩溃、服务无法启动：
必须自动执行：
```bash
git reset --hard HEAD
```

---

## 8. 永久行为准则

- 稳定优先于功能
- 小步快跑，频繁提交
- 不确定就问，不懂就停
- 永远不要破坏 MVP
- 永远不要修改环境变量逻辑
- 永远不要在 main 分支开发
- 永远不要跳过回归测试
