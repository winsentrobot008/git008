# AGI 工厂治理宪法（Codex 版）

> **适用范围**：Codex 在 VS Code 中对 `git008`（AGI 工厂）项目的全部工作行为。
> **版本**：v1.2（含 Sentinel 哨兵挂载 + API 降本治理）
> **生效日期**：2026-08-04
> **签署方**：CEO、架构师总监
> **加载机制**：本文件位于项目级 `.codex/instructions.md`，Codex 在 git008 工作区内对话时将自动加载本宪法。

---

## 铁律一（代码约束）

> 严禁破坏项目中的 **React #418 水合保护**、**多语言架构与模版逻辑** 及 **Next.js 标准配置**；修改代码后须保持规范日志输出。

- **严禁修改 / 删除 / 绕过 React #418 水合保护** 及其注释标记，任何触碰须先获得架构师总监批准。
- **严禁无意抹除多语言（i18n）与模版逻辑**：不得破坏资源结构、字典加载链路、语言切换与模版渲染逻辑。
- 不得擅自改动 `next.config.*` 等 Next.js 标准配置项，除非架构师总监书面批准。
- 所有代码改动完成后，须保持项目规范日志输出（结构化、可审计、可追踪）。

## 铁律二（职责边界）

> Codex 仅专注于 VS Code 内部的代码重构与 Bug 修复，不得擅自修改**白龙马 QA 引擎**与**调度中枢**逻辑。

- **白龙马 QA 引擎**（`factory_components/orchestrator/`、`qa_delivery/`）与**调度中枢**逻辑由对应负责人维护，Codex 无权修改。
- Codex 的职责范围仅限 VS Code 内部的代码重构与 Bug 修复。
- 若在越界模块中发现缺陷，须上报架构师总监/CEO，由负责人处置，不得自行改动。

## 铁律三（协同规范）

> 修复 Bug 时，必须读取 `qa_delivery/reports/` 目录下白龙马生成的质检报告，按报告指出的 **Fail 项** 定向修复。

- 修复前：定位 `qa_delivery/reports/` 下对应的 `inspection_*.md` 质检报告，提取 Fail 项清单。
- 修复中：仅针对报告指出的 Fail 项定向修复，不得发散式改动无关代码。
- 修复后：说明本次改动与报告 Fail 条目的对应关系，供质检复核闭环。

## 铁律四（API 降本治理）

> 为控制 DeepSeek API 成本，ZOO / Codex 必须执行以下 Token 消耗与模型分级治理，违者视为违宪。

### 4.1 上下文截断（Context Truncation）
- **历史上下文窗口上限 = 最近 8 轮对话**。超出部分须在下次调用前主动压缩 / 归档（写入记忆库或日志），严禁将全部历史无差别带入每次调用。
- **禁止默认全量读取整个 repo 文件**。进入任何项目前，须先用终端轻量命令获取目录概览（如 `list_files` / `Get-ChildItem` 顶层），再按需定点读取目标文件；严禁对未知大小目录盲目递归全量读取。

### 4.2 轻量任务分流（Task Tiering）
- **L0 本地处理（零 API 成本）**：纯命令执行、质检报告汇总、静态解析、文件操作等简单任务，一律使用本地静默脚本 / CLI 完成，严禁请求主 API。示例：[`scripts/qa_inspect.py`](scripts/qa_inspect.py)。
- **L1 轻量模型**：重构、Bug 修复、代码片段等常规编码任务，使用轻量模型（`deepseek-v4-flash`）。
- **L2 全量模型**：仅架构设计、复杂调试、治理决策等必须场景才使用全量主模型（`deepseek-v4`）。
- 分流决策先于调用：任务下达后先判定所属分级，再选择执行通道。

### 4.3 单次 Task 保护锁（Task Budget Lock）
- 单次任务设置 API 消耗上限：调用次数 ≤ 50、Token ≤ 300,000、成本 ≤ $1.00（见 `Cline-anti-freeze/clinerules.yaml` 的 `api_cost_governance`）。
- 单次任务内达到上限即触发熔断（`circuit_break`）：立即停止该任务后续 API 调用，归档已完成部分，并上报 CEO / 架构师总监，严禁进入死循环重试。
- 每完成若干轮调用须自查累计消耗，预估将超限时提前压缩上下文或降级至 L1 / L0 通道。

## 宪法·操作边界（Operation Boundary）

> 只在 `projects/` 细分目录下操作；**禁止扫描根目录 `node_modules`**。

- 所有开发/重构/Bug 修复操作必须限定在 `projects/<产品名>/` 细分目录内进行。
- **绝对禁止**对根目录（或任何子目录）`node_modules` 执行扫描、列出、读取或遍历操作。
- 进入子项目后，操作死锚在该项目目录内，严禁发散式全盘越界扫描。
- 对未知大小或中大型目录，先以终端轻量命令获取概览，再决定是否深入。

## Sentinel 哨兵（Command Timeout Guard）

> 命令单次执行超时时间硬限制：**Timeout = 30 秒**。

- 任何命令（含 PowerShell `Get-ChildItem` 等长命令）单次执行超时上限为 **30 秒**，防止陷入无限等待状态。
- 执行命令时必须显式携带超时参数（`timeout: 30`），超时后立即中止并降级处理。
- 严禁对 `node_modules`、`.git`、`dist`、`build`、`__pycache__` 等垃圾场目录发起递归扫描（此类操作极易超时，属违宪行为）。
- 若命令超时：记录原因 → 改用轻量命令/分片查询 → 仍失败则上报，不得盲目重试。

## 指令闭环

- Codex 遵循**架构师总监 → CEO** 的指令闭环执行任务，不得越级或擅自行事。
- 优先级：本宪法（硬约束） > Sentinel 哨兵 > 架构师总监指令 > CEO 指令。
- 任何涉及 React #418 水合 / 多语言模版 / Next.js 配置 / 白龙马 QA 引擎 / 调度中枢的变更，执行前须自查本宪法并声明合规。

## 合规自检

开始任何任务前，Codex 应自问：

1. 本次改动是否触碰铁律一保护域（React #418 / 多语言模版 / Next.js 配置）？若触碰，是否已获得批准？
2. 本次改动是否越出铁律二职责边界（白龙马 QA 引擎 / 调度中枢）？若越界，应上报而非修改。
3. 本次 Bug 修复是否已读取 `qa_delivery/reports/` 对应质检报告并锁定 Fail 项？
4. 本次操作是否限定在 `projects/<产品名>/` 内？是否已避开根目录 `node_modules`？
5. 本次命令是否已设置 **Timeout = 30s** 哨兵，避免长命令无限等待？
6. 本次任务是否已判定模型分级（L0 本地 / L1 轻量 / L2 全量）？上下文是否保持在最近 8 轮内、未默认全量读取 repo、且未超出单次任务预算保护锁？
