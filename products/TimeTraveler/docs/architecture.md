# TimeTraveler — 系统架构文档

## 整体数据流

```
用户上传视频
    ↓
┌──────────────────────────────────────────┐
│              本地预处理                    │
│  (app/core/preprocessor.py)              │
│  ├─ 视频解码 → 帧序列                     │
│  ├─ 人脸检测 → 脱敏 / 模糊                │
│  ├─ 场景分割 → 关键帧提取                 │
│  ├─ 情绪分析 → 情绪标签 + 时间线          │
│  └─ 打包 → 匿名化特征包 (.afp)           │
└──────────────────────────────────────────┘
    ↓ .afp (匿名化)
┌──────────────────────────────────────────┐
│              云端加速                      │
│  (cloud/gs_engine/)                      │
│  ├─ 4D Gaussian Splatting 场景重建        │
│  ├─ AI 角色生成 + 情绪注入               │
│  ├─ 光照 / 物理模拟                      │
│  └─ 返回加密 4D 场景包                   │
└──────────────────────────────────────────┘
    ↓ 加密场景包
┌──────────────────────────────────────────┐
│              本地渲染                      │
│  (4d_engine/rendering/)                  │
│  ├─ 本地 GPU 实时渲染                     │
│  ├─ AI 角色实时对话                       │
│  ├─ 交互反馈循环                         │
│  └─ 数据不出房间                          │
└──────────────────────────────────────────┘
```

## 本地预处理流程

### 1. 视频输入处理
- **输入**: MP4/MOV/WebM 视频文件
- **流程**: FFmpeg 解码 → 帧序列 → 场景检测 → 关键帧提取
- **输出**: 关键帧列表 + 场景元数据

### 2. 隐私脱敏
- **人脸检测**: YOLOv8 或 MediaPipe
- **脱敏方式**: 高斯模糊 / 马赛克 / AI 重绘
- **敏感信息**: 车牌、身份证、屏幕文字等 OCR 检测后模糊

### 3. 情绪特征提取
- **模型**: 轻量级多模态情绪识别
- **输入**: 关键帧 + 音频轨迹
- **输出**: 情绪标签 (happy/sad/calm/excited/...) + 时间线 + 置信度

```
      "dominant_colors": [...]
    }

```

## 云端加速流程

### 1. 4D 场景重建 (Gaussian Splatting)
- **输入**: 匿名化特征包
- **引擎**: 自研 4D GS 加速引擎
- **处理**: 稀疏重建 → 密集化 → 4D 优化
- **输出**: 可渲染的 4D Gaussian 场景

### 2. AI 角色生成
- **输入**: 情绪时间线 + 场景元数据
- **模型**: 基于情绪状态的动态角色生成
- **输出**: AI 角色配置 (外观/性格/声音)

### 3. 场景包加密返回
- **加密**: AES-256-GCM + 用户公钥
- **传输**: HTTPS + 双向 TLS
- **格式**: 加密的 4D 场景包 (.4ds)

## 本地渲染流程

### 1. 场景解密
- 使用用户私钥解密 4D 场景包
- 验证完整性签名
- 加载到 GPU 显存

### 2. 实时渲染
- **引擎**: Vulkan / WebGPU
- **技术**: 实时 Gaussian Splatting 渲染
- **交互**: 鼠标/手柄 6-DoF 漫游
- **性能**: 目标 30fps @ 1080p

### 3. AI 互动
- **对话**: 本地 LLM (Llama/Gemma 量化版)
- **情绪反馈**: 根据对话内容实时调整场景氛围
- **记忆**: 短期记忆 (会话) + 长期记忆 (房间数据库)

## 房间加密机制

```
用户主密钥 (User Master Key)
    ↓ HKDF
├─ 房间加密密钥 → AES-256-GCM 加密所有房间数据
├─ 身份签名密钥 → Ed25519 签名所有操作
└─ 会话派生密钥 → 每次对话生成唯一密钥
```

## 人物 3D 模型真实度与稳定性（Avatar Realism System）

### 1. 背景与目标
在 4D穿越者（4D TimeTraveler）系统中，用户将进入由视频生成的 3D/4D 世界。为了保证沉浸体验，人物模型必须尽量真实、不变形、不漂浮、不扭曲、不产生恐怖谷效应，并在场景中自然存在。本章节定义人物模型的技术路线、稳定性策略与真实度等级。

### 2. 视频生成人物变形的技术原因
从单视角视频重建人物时，系统必须从不完整信息推断完整几何，因此会出现：
- 几何不准确（身体比例偏差）
- 深度不稳定（手臂、头部漂浮）
- 纹理拉伸（衣服变形）
- 边缘漂移（头发、手指抖动）
- 光照不一致（人物与场景不匹配）

这些现象属于视频 → 3D 重建的自然限制。

### 3. 解决方案：人物替身模型（Avatar Proxy）
采用 Avatar Proxy 技术路线，不直接重建人物，而是：
1. 从视频提取人物特征
2. 构建稳定的 3D 替身模型
3. 用 AI 修复纹理
4. 将替身模型放入 4D 世界

替身模型的优势：
- 几何稳定
- 身体比例真实
- 面部自然
- 衣服不变形
- 动作平滑
- 光照可匹配场景
- 不会出现恐怖谷效应

### 4. 人物替身模型构建流程（技术路线）
**步骤 1：人物检测** — MediaPipe / YOLO

**步骤 2：姿态估计** — OpenPose / MediaPipe Pose

**步骤 3：身体重建** — SMPL / SMPL-X

**步骤 4：面部重建** — DECA / 3DMM

**步骤 5：纹理生成与修复** — 视频纹理贴图 + AI 修复

**步骤 6：动作重建** — Video Mocap

**步骤 7：光照匹配** — AI Relighting

### 5. 人物真实度等级（用户可选择）
**等级 1：柔和真实（默认）** — 面部略简化，适合情绪场景。

**等级 2：真实人物（沉浸模式）** — 面部真实、衣服真实，适合记忆场景。

**等级 3：超真实（高级付费）** — 高精度面部、皮肤纹理真实，适合高端用户。

### 6. 记忆流动效果（Memory Flow）
轻微的模型柔化与场景流动被设计为记忆体验：
- 墙壁轻微流动
- 光线漂移
- 人物边缘柔化
- 空间呼吸感

让用户感觉"我真的进入了自己的记忆"。

### 7. 场景中的人物存在感（Presence System）
采用：
- 场景光照匹配
- 阴影投射
- 地面接触检测
- 遮挡关系
- 空间音效匹配

确保人物自然融入场景。

### 8. 用户体验目标
进入 4D 世界后，用户应感受到：
- 人物真实但不恐怖
- 自然融入场景
- 动作平滑
- 情绪体验真实
- 沉浸感强

最终目标："这就是我记忆中的那个人。"

## 互动游戏特质（Interactive Game Nature）

### 1. 项目本质
4D穿越者不仅是一个情绪空间产品，它本质上具备完整的互动游戏特质。用户进入由视频生成的 4D 世界，与 AI 角色互动、触发事件、体验剧情，这些都属于游戏引擎级的交互体验。

### 2. 游戏世界（Game World）
系统生成的 4D 场景本质上是一个可进入的游戏世界，包括：
- 记忆世界
- 情绪世界
- 关系世界
- 心理世界

每个房间都是一个关卡（Level）。

### 3. 游戏角色（AI NPC）
AI 角色具备：
- 对话能力
- 情绪理解
- 行为触发
- 剧情引导
- 场景互动

这是游戏中的 NPC（Non-Player Character）。

### 4. 游戏事件系统（Trigger System）
系统支持事件触发：
- 用户触碰物体 → 情绪事件
- 用户走到某位置 → 记忆事件
- AI 角色说话 → 场景变化
- 用户选择 → 剧情分支

### 5. 游戏叙事系统（Narrative System）
用户体验完整的叙事流程：
- 进入过去
- 体验情绪
- 与 AI 角色互动
- 触发剧情
- 走向结局

### 6. 游戏状态机（Game State Machine）
用户情绪状态作为游戏状态：
- Calm
- Sad
- Nervous
- Healing

场景与 AI 角色根据状态变化。

## 视频动作捕捉系统（Video Motion Capture System）

### 1. 目标
从用户视频中提取人物动作，并将动作应用到 3D 替身模型，使人物在 4D 世界中自然存在。

### 2. 为什么动作捕捉重要
- 让人物动作真实
- 让人物不漂浮、不僵硬
- 让记忆人物自然融入场景
- 让 AI 角色与人物互动更自然

### 3. 开源动作捕捉方案（可直接使用）
本项目采用成熟的开源 Video Mocap 技术：

**首选：**
- VIBE（稳定、成熟）
- PARE（遮挡更强）

**可选：**
- ROMP（速度快）
- MotionBERT（动作平滑）

### 4. 动作捕捉流程
1. **人物检测**：MediaPipe / YOLO
2. **姿态估计**：OpenPose / MediaPipe Pose
3. **动作重建**：VIBE / PARE
4. **身体模型**：SMPL / SMPL-X
5. **面部模型**：DECA
6. **动作平滑**：MotionBERT（可选）
7. **场景融合**：光照匹配、阴影、接触检测
